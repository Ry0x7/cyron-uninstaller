# Code Signing and Release Integrity Policy

## 1. Overview and Status

This document defines the code-signing standards, key-management policies, release integrity checks, and privacy commitments for **Cyron Uninstaller**.

All official releases and installers are signed under the authority of the **Chryypt Organization** (`CN=Chryypt Organization`, publisher `Chryypt`).

---

## 2. Build Classifications and Release Gates

All binaries and release bundles generated by this repository are strictly classified into two categories:

| Classification | Signature Status | Intended Distribution | Security & Trust Guarantee |
|---|---|---|---|
| `UNSIGNED_RC` | None | Private testing & development | No signature; verify SHA-256 hash against published release checksums. |
| `CHRYYPT_SIGNED` | Signed (`CN=Chryypt Organization`) | Official releases & installers | Authenticode signed with SHA-256 digest under Chryypt Organization authority; cryptographically intact. |

### CI/CD Security Invariants:
1. **Signer Identity Enforcement:** Verification automation asserts that any signed release matches `CN=Chryypt Organization`.
2. **False Claims Rejection:** Any unsigned binary falsely labelled as signed is rejected.
3. **Commit Provenance:** Every public release candidate records the exact source Git commit SHA and provides reproducible build artifacts.
4. **Metadata Alignment:** The file version, product version, publisher (`Chryypt`), and MSI UpgradeCode must match project configuration.

---

## 3. Contributor, Reviewer, and Release Approver Responsibilities

### Maintainers and Release Approvers:
- Must have GitHub Two-Factor Authentication (MFA) enabled.
- Must verify that all test suites (`npm test`, `cargo test`, `security.rs`, `real_system.rs`, `cleanup_stress.rs`, `stress_scan.rs`) pass completely before initiating any release.
- Must ensure release bundles are verified with `npm run verify:signatures` and `npm run verify:metadata`.
- Must ensure private signing keys or certificates are never committed to public version control.

### Contributors:
- Must adhere to the strict principle that scanning operations remain 100% read-only.
- All destructive operations (uninstallation, process termination, leftover cleaning) must use server-held, single-use, expiring confirmation plans.
- Files must be quarantined, never permanently deleted in-place without explicit user review.

---

## 4. Privacy Policy and System Modification Disclosures

Cyron Uninstaller is committed to complete user transparency and privacy:

1. **Zero Network Telemetry:**
   Cyron Uninstaller contains zero network communication code. It does not send telemetry, analytics, diagnostics, crash reports, or user data to any external server.
2. **Local-First Processing:**
   All scanning, disk analysis, duplicate verification, and inventory discovery occur entirely on the local device.
3. **Review-First System Modifications:**
   - **Cleaner:** Files moved to quarantine are stored in `%APPDATA%\dev.cyron.uninstaller\quarantine` with a durable write-ahead recovery journal (`recovery_journal.jsonl`). Quarantined batches can be restored to their original locations or purged permanently upon explicit user command.
   - **Uninstaller:** Application uninstallation invokes only registered vendor uninstall commands. Force process termination protects critical Windows processes and requires explicit confirmation. Leftover registry deletion automatically creates `.reg` backups before any subkey is removed.
   - **Explorer Integration:** Shell verbs are registered per-user under `HKCU\Software\Classes` without administrative elevation, and can be cleanly removed via Settings at any time.

## 5. Verification Instructions for Users

Users and auditors can independently verify the cryptographic integrity of any Cyron binary using standard Windows tools:

### Using PowerShell:
```powershell
# Check Authenticode signature
Get-AuthenticodeSignature ".\Cyron Uninstaller_0.1.0_x64-setup.exe" | Format-List *

# Check SHA-256 hash
Get-FileHash ".\Cyron Uninstaller_0.1.0_x64-setup.exe" -Algorithm SHA256
```

### Using Windows SDK SignTool:
```powershell
signtool verify /pa /v ".\Cyron Uninstaller_0.1.0_x64-setup.exe"
```

For `CHRYYPT_SIGNED` releases, `Get-AuthenticodeSignature` will report `Status: Valid` (or untrusted root if not in system root store) with `SignerCertificate.Subject` matching `CN=Chryypt Organization`.
