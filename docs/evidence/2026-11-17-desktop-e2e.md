# Real desktop E2E — 2026-11-17

This receipt records the first reproducible Windows desktop acceptance run against the compiled Tauri
application. It replaces assertions made from JSX, unit tests or browser-only previews with
WebView2/WebDriver evidence from the real executable.

| Item | Value |
|---|---|
| Git revision | `3d9f2daddb527492afc578c43dc70c1a7a7ce6f2` plus the uncommitted Phase 8 working tree |
| Application | `src-tauri/target/debug/cyron.exe` (embedded production frontend) |
| Driver | `tauri-driver` + matching Microsoft Edge WebDriver (`157.0.4341.46`) |
| WebView2 runtime | `157.0.4341.46` |
| Node.js | `v24.18.0` |
| OS | Windows 11 x64, real interactive desktop session |
| Window sizes | 1320×860 default, 1000×680 minimum, 1440×960 large |
| Themes | System/dark and Light, persisted across a real page reload |

The suite runs inside the current Windows profile because WebView2 does not start reliably under a
redirected `USERPROFILE`. It isolates itself with disposable HKCU uninstall/startup entries, a
temporary workspace, a single disposable Yarn cache file under the real cache folder, and a
backed-up Cyron app-data directory. The app-data directory, HKCU fixture keys and temp workspace are
removed or restored afterwards.

`npm run test:desktop -- --spec tests/desktop/01-core.spec.mjs`.

## Fixes made by this harness

- **Display scaling:** WebDriver pointer clicks landed on the wrong sidebar row at this machine's
  Windows scale factor. The suite now dispatches clicks on the resolved element, which fixed storage
  navigation, sorting and the second checkbox selection.
- **Fixture uninstaller contract:** the generated uninstaller command omitted `--subkey`, so the
  fixture exited 2 and the app correctly refused to claim removal. The harness now generates the
  registered command the fixture expects.
- **Interrupted-run residue:** stale HKCU fixture entries doubled the application rows. Fixture setup
  now removes only its own `CyronDesktopE2E_*` and `CyronDesktopE2EStartup_*` entries before creating
  a new run.
- **WebView2 profile portability:** redirected `USERPROFILE`/`APPDATA` broke WebView2 startup and
  produced `DevToolsActivePort` failures. The suite runs in the real profile and isolates app state by
  backup/restore instead.
- **UI Automation helper:** removed an invalid unused `PropertyCondition` construction that made every
  UIA action throw.

## Limitations — explicitly UNVERIFIED

- **125% and 150% OS display scaling** were not switched during this run. WebView2 reported at the
  machine's current scale; changing Windows scale requires a sign-out. The 1000×680 and 1440×960
  CSS-pixel sizes were tested, but the 125%/150% matrix remains UNVERIFIED.
- **Native `ask` confirmation for startup toggles** was not completed. The WebDriver-triggered click
  produced no native dialog window that UI Automation could find, so the test was reduced to startup
  provenance and the toggle round-trip remains UNVERIFIED in automation. The UIA helper is in place
  for a manual or fixed run.
- **Installer, upgrade and relaunch** were not exercised by this harness. The per-user NSIS install,
  repair, relaunch, uninstall and reinstall path was closed separately by
  [the installer receipt](2026-11-17-installer-release.md); the MSI, cross-version upgrade and
  clean-VM install remain UNVERIFIED.
- **Real cache cleanup and quarantine restore** were deliberately not executed. Running the Cleaner
  would move this machine's actual cache directories. The existing Rust cleanup fixtures and the
  prior native Projects receipt remain the evidence for quarantine execution; this harness did not
  add cache-execution evidence.
- **AI/project cleanup, protected-data refusal, duplicate scanning and treemap interaction** were not
  executed. Their UI states are covered elsewhere, but this desktop suite did not select a folder
  through the native picker or scan a real project.
- **Explorer shell verbs, Microsoft Store/MSIX removal, UAC presentation, vendor installers and a
  clean-VM release install** remain UNVERIFIED in the desktop harness.
- Screenshots contain this machine's real application inventory and paths. They are acceptance
  evidence, not a synthetic design fixture; no user cache or project was cleaned.
