# Cyron — Implementation Status

Last updated: 2026-11-26 (0.2.4 release: read-only System health scan for dead Run/RunOnce startup values and dead uninstall registrations, with review-first removal behind single-use plans and restorable `.reg` backups; earlier: 0.2.3 release: native read-only search index replacing the Everything IPC client, fixed-drive metadata index, persistent cache, live watchers, Everything-style query language, filters, sortable results, multi-select and CSV/TXT export; earlier: v0.2.2 published with the in-app updater and read-only Everything 1.4.1+ IPC search; 0.2.1 packaging release: Chryypt publisher and file identity in the NSIS setup and uninstaller, branded installer and uninstaller icons, homepage ARP/Help links, hardened Windows metadata gate; earlier: native desktop verification of the spike capture and driver evidence; kernel/driver performance evidence and batch-eligibility fix; v0.2.0-rc.2 unsigned prerelease published after green release and CI workflows; v0.2.0-rc.1 unsigned prerelease; 0.2.0 release-candidate build and NSIS verification; Phase 8 independent release audit; workflow UX completion; design-system rebuild, performance diagnostics and startup evidence, implementation ledger)

## Summary

Cyron Uninstaller is a verified Tauri v2 desktop application on Windows 10/11 x64 featuring:
- Multi-source application inventory (Win32 64/32-bit, Microsoft Store / AppX / MSIX through the Windows Runtime package manager, Steam game libraries, and portable heuristic scanning with PE version metadata).
- Vendor uninstallation reconciliation with bounded post-exit inventory verification and explicit 1605/1614, 1602, 3010/1641 and still-registered outcomes.
- Current-user Microsoft Store / MSIX removal through a server-held plan and `RemovePackageAsync`, without shells, `RemoveForAllUsers` or machine-wide deprovisioning.
- Persistent installed/removed application lifecycle history across restarts (2,000 records).
- Process discovery, snapshot-verified termination with critical-process protection and PID recycling prevention.
- Leftover scanning with confidence & risk ratings, automatic recursive multi-type `.reg` backup, and quarantine storage.
- Sequential batch uninstallation with failure isolation, limited to registered Win32 vendor uninstallers; Store, Steam, portable and broken entries cannot be queued.
- Interactive disk space analyzer with Squarified treemap and persistent virtualized folder tree (220–520 px).
- Dual scan engine: elevated NTFS MFT volume parsing with automatic streaming directory-walk fallback.
- 3-stage duplicate file verification with hard-link deduplication.
- Storage categorization into 10 categories with known vs inferred confidence ratings.
- Review-first cache cleaner over extensible declarative providers (`schema_version: 1`).
- Crash-consistent recoverable quarantine with durable write-ahead recovery journal (`recovery_journal.jsonl` with `sync_all`), atomic Win32 `MoveFileExW` no-overwrite restoration, and manifest-scoped purging.
- Windows Explorer context menu integration (`HKCU\Software\Classes`) with safe argument routing.
- Read-only dead-entry scanner for orphaned Run/RunOnce startup values and uninstall registrations, with review-first, journaled removal and a verified `.reg` backup that can be restored.
- Native, read-only **Search** destination built on Cyron's own fixed-drive metadata index: compact in-memory entries, atomic persistent cache, background startup load, recursive file-system watchers, bounded query parser with Everything-style field syntax, type filters, sortable/paged results and no execution surface. Everything does not need to be installed; file contents are never read.
- User-initiated in-app updates from Settings → About: signed GitHub Releases manifest, progress, native confirmation, verified NSIS package and restart. No background polling or telemetry. The updater private key is never bundled; the public key is embedded.
- Standardized Windows PE VERSIONINFO, WiX MSI properties, and NSIS installer headers (`WINDOWS_METADATA_OK`). The 0.2.1 packaging pass adds the Chryypt `CompanyName`, `InternalName` and `OriginalFilename` keys to the NSIS setup and uninstaller, the Cyron icon for both, and homepage-backed ARP/Help links.
- Local Chryypt Organization self-signed signing pipeline. Cryptographic integrity is separate from public trust: the published `v0.1.0` installer, the 0.2.0 RC1 and RC2 artifacts, and the v0.2.2 installer/MSI/standalone executable are `NotSigned`; the v0.2.2 updater package carries a separate minisign signature. The certificate is self-signed.
- Evidence-bound performance diagnostics: live CPU, memory, PDH disk, process, startup and scheduled-task evidence; a 20-second burst capture for intermittent spikes; read-only display/storage/network driver versions and recent System driver/device events; reversible startup toggles behind a native confirmation; local before/after baselines; optional administrator-only WPR trace; no placebo tuning.
- Seven-destination Windows-native interface (Home, Search, Applications, Storage & Cleanup, Performance, History & Recovery) with Settings in the sidebar footer, a shared token/primitive system, keyboard-visible focus, dialog focus trapping and reduced-motion support.
- Verified release packaging: NSIS setup installer, WiX MSI package, and standalone executable (`RELEASE_BUNDLES_OK`). The 0.2.0 RC1 per-user NSIS package was installed, launched, uninstalled and reinstalled with app data preserved; same-version repair was verified on 0.1.0. The MSI is per-machine and still requires an elevated install test. `v0.2.0-rc.2` was published as an unsigned GitHub prerelease after release workflow `44157576637` passed; `main` CI run `44156171511` is green. The downloaded rc.2 checksums verified all three artifacts, and all three report `NotSigned`. `v0.2.2` was published on 2026-11-25 after release workflow `45452657763` passed; the downloaded `SHA256SUMS.txt` verified all four hashed assets and the live updater manifest advertises only `windows-x86_64-nsis`. A fresh 0.2.1 installation upgraded with the published 0.2.2 setup and then updated to 0.2.3 in-app on 2026-11-26 (GATES.md G134).

## Phase 8 release audit (2026-11-17)

The independent audit is recorded in [docs/RELEASE_AUDIT_2026-11-17.md](RELEASE_AUDIT_2026-11-17.md). Its result is **NOT PRODUCTION READY — release blocked** on external trust and unexercised native paths, not on a known data-loss defect found by the suites.

- **Passed in this tree:** 112 frontend tests in 14 files; typecheck; `DOCS_CHECK`; 265 Rust tests passed with 4 ignored; cleanup and 8-scenario RC1 fixtures; 10 real desktop WebView2 journeys; Cyron-only three-run scanner measurements.
- **Fixed:** Force Delete junction retargeting and path-only TOCTOU, cross-volume quarantine dropping links, manifest-scoped restore escape, PID-reuse window during graceful termination, and provider definitions labelling protected data as `caution`.
- **Packaging and installer:** NSIS setup and WiX MSI built with hashes recorded; metadata audit passed. The 0.1.0 audit verified same-version repair; the 0.2.0 RC1 fresh install, launch, uninstall and reinstall passed with the 60,024-file app-data tree unchanged. The MSI returns MSI error 1925 without elevation and was not installed elevated. See [the 0.1.0 installer receipt](evidence/2026-11-17-installer-release.md) and [the 0.2.0 RC1 receipt](evidence/2026-11-18-release-0.2.0.md).
- **Release blockers:** the local installer is unsigned and not publicly trusted (the published `v0.1.0` NSIS asset is also `NotSigned`); real MSI, vendor and Store/MSIX removal are unverified; elevated MSI is unverified while cross-version NSIS upgrade and downgrade are verified (G134, G135); elevated MFT, boot-impact and WPR paths are unverified; 125%/150% scaling and screen-reader traversal are unverified.
- **Competitors:** no competitor product was installed or run. [docs/COMPETITOR_COMPARISON.md](COMPETITOR_COMPARISON.md) is a documented-capability matrix and marks every comparative scenario **NOT RUN**.

## Known Limitations & Design Boundaries

1. **Store / MSIX Lifecycle:** Current-user packages are removed natively through `PackageManager::RemovePackageAsync` behind a single-use plan. Cyron does not call `RemoveForAllUsers`, deprovision, elevate automatically or launch `winget`/PowerShell. Machine-wide and provisioned packages require Windows Settings or an administrator-managed tool. A real package removal through the desktop UI is UNVERIFIED as of 2026-11-16.
2. **Portable Applications:** Standalone portable executables in `%LOCALAPPDATA%\Programs` are discovered through explainable heuristics. They lack registry uninstaller commands; Cyron provides residual scanning, folder measurement, and Explorer navigation.
3. **MFT Scanner Elevation:** Accessing raw volume handles (`\\.\X:`) requires administrator elevation. When unelevated, Cyron reports the reason and falls back seamlessly to the streaming directory walk.
4. **MFT vs Walk Counting Difference:** The MFT reader counts physical NTFS records; the streaming directory walk counts accessible filesystem paths (deduplicating up to 1,000,000 hard-link IDs). Volume totals from the two methods differ by design (see [docs/BENCHMARKS.md](BENCHMARKS.md)).
5. **Desktop Build Modes:** `npm run dev:desktop` uses the Vite dev server. `npm run build:desktop` builds a debug executable with embedded production assets and runs standalone; this is the executable used for the Phase 5 native review. Release bundles embed assets as well.
6. **Platform Scope:** Cyron targets Windows 10/11 x64 exclusively. Win32 APIs are invoked unconditionally.
7. **Release Signing Trust:** The GitHub release workflow builds unsigned artifacts. Local signing uses a self-signed certificate, which is cryptographically verifiable but not publicly trusted. Release copy must not imply SmartScreen trust.
8. **Cross-Volume Folder Restore:** `restore_batch` stages a quarantined folder on the destination volume, publishes it with a no-overwrite rename, and only then removes the quarantined copy. A tree containing a link or junction is refused and left in quarantine rather than silently dropping the link. Unit tests cover staging, conflict refusal and folder round-trip; a native E:→C: quarantine→restore run through Cleaner verified the full path on 2026-11-16.
9. **Scan Index IPC:** `query_directory_children`, `search_indexed_files` and `get_scan_index_stats` are registered and index data is built during scans, but no current view calls them. They are dead IPC until a tree/search view consumes the index.
10. **Project Discovery Is Bounded, Not Exhaustive:** Automatic candidates cover common profile/drive folders; projects elsewhere require **Add project folder**. Scanning stops at 60,000 directories, 400 projects and 24 roots. It does not index every file on a drive.
11. **Project Activity Is Heuristic:** Activity uses project, manifest and Git timestamps, not open handles or editor sessions. An old label is never permission to clean; every artifact is unselected until the user chooses it.
12. **Artifact Rebuild Is Not Executed:** Cyron shows the official rebuild/prune command (`npm ci`, `cargo clean`, `pytest --cache-clear`, `ruff clean`, `hf cache prune`, etc.) but never launches a package manager, model CLI or shell. This preserves the no-arbitrary-command boundary.
13. **Next.js Cache Caveat:** Only `.next/cache` is offered; `.next` output and runtime ISR data are not. A self-hosted server can use filesystem-backed ISR data that regenerates only if its upstream data still exists; the preview says so and marks the artifact caution.
14. **Per-Drive and Custom Tool Stores:** Cyron uses documented default cache paths. pnpm per-drive `.pnpm-store`, custom `UV_CACHE_DIR`, `PIP_CACHE_DIR`, `HF_HOME`, `OLLAMA_MODELS`, Yarn PnP/Zero-Installs caches and other overridden locations are not discovered automatically; the owning tool's own command is the correct path. LM Studio's documented model/conversation paths and legacy cache are both protected.
15. **Native Desktop UI:** The Projects tab was driven end to end in the native Tauri build on 2026-11-17 (Windows UI Automation), including preview, quarantine, verification, restore and a second volume. This is recorded in GATES.md G78 with screenshots. The run used disposable projects only; no real user project or cache was cleaned.
16. **Performance Is a Short Sample:** CPU, memory, disk and process figures describe one 700 ms window every ten seconds, not a lifetime average. The optional 20-second capture narrows the gap but still records about one reading per second; a spike between those readings is missed. Per-process I/O combines file, network, pipe and device transfers, and the counters do not attribute DPC/ISR time to a named driver. Cyron does not measure temperature or fan speed.
17. **Elevated Performance Paths:** Per-app boot impact requires the administrator-only Diagnostics-Performance log, and WPR tracing requires an administrator session. The unelevated UI says so and disables tracing; both elevated paths are UNVERIFIED as of 2026-11-17. Driver evidence and the System event log are read-only and unelevated; access denied is reported instead of treated as an empty result.
18. **Baselines Show Association:** Two local samples can show that a number changed, not that a change caused a speed improvement. The UI says this explicitly and never reports a guaranteed gain.
19. **Visual Accessibility Is Not Certified:** Keyboard order, visible focus, dialog trapping, Escape return and reduced motion were exercised in the native build. Narrator/NVDA traversal, Windows forced-colors rendering and 200% OS text scaling were not; those remain manual accessibility gates.
20. **Screenshots Use This Machine's Inventory:** The committed Phase 5, Phase 6 and Phase 7 captures show this machine's installed applications and volumes plus disposable fixtures. They are acceptance evidence only; no real user cache or project was cleaned for them.
21. **Desktop E2E Scope Is Fixture-Bound:** The real desktop suite proves navigation, inventory controls, uninstall execution, registry backup/restore, settings persistence, measured Performance content and Hunter lifecycle. It does not execute Cleaner quarantine, project cleanup, duplicate scanning, treemap drills, Explorer verbs or Store/MSIX removal. The NSIS installer path was verified separately, including cross-version upgrade and downgrade (G134, G135); MSI installation remains UNVERIFIED.
22. **DPI Matrix Is Incomplete:** Windows cannot change display scale without a sign-out, so the suite verified 1000×680 and 1440×960 CSS-pixel sizes at the current scale. 125% and 150% rendering remains a manual gate.
23. **Native Confirmation Automation Is Incomplete:** `scripts/desktop-uia.ps1` can list, inspect and invoke native windows, but the Tauri `ask` dialog for startup toggles did not appear as a discoverable top-level window under the WebDriver run. The startup toggle round-trip should be completed manually or with a fixed harness before claiming native-dialog automation.
24. **MSI Is Per-Machine:** The WiX package requires administrator elevation and returned MSI error 1925 when run without it. Only the NSIS current-user package has a verified per-user install path. An elevated MSI install, upgrade and uninstall remains a manual gate.
25. **Cross-Version Installer Coverage:** The NSIS package was reinstalled over `0.1.0`; version-to-version upgrade (0.2.1 → 0.2.2 → 0.2.3) and downgrade (0.2.3 → 0.2.2) were executed on 2026-11-26 with history and quarantine intact (G134, G135). A clean-VM install remains unexecuted.
